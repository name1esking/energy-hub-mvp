# Energy Hub — словарь показателей по DATA_MODEL.md v0.1

**Источник:** `DATA_MODEL.md`, разделы 5–6 и 9. **Статус модели:** Draft.  
Коды `metric` ниже — **временные локальные значения**, а не утверждённый командный enum: в документе приведены русские названия, но не указаны машинные идентификаторы.

## 1. Семь согласованных показателей Measurement

| `metric` (предложенный код) | Название из модели | `unit` | Семантика и агрегация |
|---|---|---|---|
| `consumption_power` | Потребляемая мощность | `кВт` | Средняя за час, не суммировать мощности разных часов. |
| `generation_power` | Генерируемая мощность | `кВт` | Средняя AC-мощность за час. |
| `consumption_energy` | Энергия потребления | `кВт·ч` | За час, вкл. нагрузку зарядной станции. Суммировать только полные периоды. |
| `generation_energy` | Выработанная энергия | `кВт·ч` | AC-выработка за час; суммировать за полные периоды. |
| `grid_export_energy` | Отдача энергии в сеть | `кВт·ч` | Экспорт за час; допустим настоящий ноль. |
| `battery_soc` | Уровень заряда батареи | `%` | SOC на конец часа, от 0 до 100; для периода брать последний доступный (с учётом `quality`). |
| `power_limit` | Лимит мощности | `кВт` | Максимум средней мощности потребления за час, по объекту. |

Все названия полей записи соответствуют модели:

```ts
interface Measurement {
  id: string
  siteId: SiteId
  metric: MetricId
  value: number | null
  unit: 'кВт' | 'кВт·ч' | '%'
  timestamp: string
  quality: 'complete' | 'missing' | 'stale' | 'estimated' | 'simulated'
}
```

`timestamp` в демо — UTC ISO 8601, **начало** часового интервала. Интервал — 60 минут; отдельное поле интервала в модели не утверждено. Поэтому **1 кВт средней мощности за один час = 1 кВт·ч энергии**. Это не тождество между единицами: в данном демо числовые значения совпадают именно из-за 1-часового интервала.

## 2. Качество данных и расчётные показатели (НЕ Measurement)

| Показатель для UI | Ед. | Формула / смысл |
|---|---|---|
| Полнота показаний, `completenessPercent` | `%` | `100 × count(value !== null) / expectedMeasurements`. |
| Индекс качества, `qualityScorePercent` | `%` | `100 × Σweight(quality) / expectedMeasurements`. Веса: `complete=1`, `simulated=1`, `estimated=0.5`, `stale=0.25`, `missing=0`. Это **демонстрационное предложение**, не утверждённый стандарт Tech Lead. |
| Расчётный импорт из сети, `derivedGridImportKwh` | `кВт·ч` | `max(потребление − генерация + экспорт, 0)` при простое батареи; иначе формула требует учёта заряда/разряда. Не выдавать за показание счётчика. |
| Собственное потребление PV, `solarSelfConsumedKwh` | `кВт·ч` | `генерация − экспорт`. |
| Доля собственного потребления PV, `solarSelfConsumptionPercent` | `%` | `100 × (генерация − экспорт) / генерация`; если генерация = 0, результат `null`, не 0%. |
| Превышение лимита, `getLimitExcessPowerKw()` | `кВт` | `max(потребляемая мощность − лимит, 0)`. |

**Важно:** расчётный импорт не относится к таблице Measurement `DATA_MODEL.md v0.1` (там указан только экспорт). Для настоящего независимого энергобаланса требуется согласовать измерение импорта и, при работе батареи, потоков заряда/разряда с Tech Lead.

## 3. Как понимать `quality`

| `quality` | Смысл по модели | `value` в демо | Отображение |
|---|---|---|---|
| `complete` | Показание получено | Число | Показывать как полученное (внутри синтетического сценария). |
| `missing` | Показания нет | **`null`** | «Нет данных»; никогда не превращать в 0. |
| `stale` | Устаревшее | Число | Помечать как устаревшее. Без поля `receivedAt` автоматически рассчитать задержку нельзя. |
| `estimated` | Расчётное | Число | Помечать как оценку. |
| `simulated` | Демо | Число | Помечать как демонстрационные данные. |

Модель пока использует единственное поле `quality`: оно не позволяет одновременно отметить «симулированное» и «полученное/оценённое». Предлагается отдельно согласовать `source`/`isSimulated` либо правила приоритетов, но **не добавлять поля самостоятельно**.

Неверное числовое значение может иметь формально допустимое `quality='simulated'`: отдельного качества `invalid` в модели нет. Поэтому файл `invalidExamples.ts` отделён от основного набора; функция `validateMeasurement()` обнаруживает отрицательную энергию, SOC выше 100%, неверную единицу и несовместимость `null` с `quality`.

## 4. Правила нулей и пропусков

- `value: 0` — показание получено и равно нулю, например ночная солнечная генерация или отсутствие экспорта.
- `value: null, quality: 'missing'` — значение неизвестно.
- Нельзя вычислять импорт/процент на неполном наборе: возвращать `null`.
- Суточная сумма энергии становится `null`, если отсутствует хотя бы один обязательный час; неполные сутки не маскируются «полной» суммой.
- Энергия измеряется в `кВт·ч`, мощность в `кВт`, SOC и показатели качества в `%`.
