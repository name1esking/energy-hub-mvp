# Пользовательские сценарии

Сценарии используют только четыре роли и сущности из `DATA_MODEL.md`.

## US-01. Администратор просматривает состояние платформы

**Роль:** `platform_admin`  
**Сущности:** `User`, `Portfolio`, `Site`, `Dashboard`, `Asset`, `Measurement`, `Event`, `ServiceInstance`  
**Статус:** просмотр — предложение для MVP; административное управление моделью не описано.

1. Администратор открывает приложение.
2. Выбирает доступный `Portfolio` или `Site`.
3. Открывает `Dashboard`.
4. Просматривает оборудование, показатели, события и подключённые сервисы.
5. Проверяет, что отсутствующие данные и проблемы качества отображаются корректно.

**Ожидаемый результат:** администратор видит демонстрационную картину доступных объектов. Нельзя считать, что он может создавать пользователей или менять конфигурацию: таких операций модель не описывает.

## US-02. Владелец портфеля сравнивает объекты

**Роль:** `portfolio_owner`  
**Сущности:** `Portfolio`, `Site`, `Dashboard`, `Measurement`, `Asset`, `Event`, `ServiceInstance`  
**Статус:** частично поддерживается; нужна связь `User` с `Portfolio`.

1. Пользователь открывает назначенный ему `Portfolio`.
2. Видит входящие в него `Site`.
3. Выбирает два объекта для просмотра.
4. Сравнивает доступные показатели с одинаковыми метриками и единицами.
5. Открывает `Dashboard` одного из объектов.
6. Просматривает оборудование, события и подключённые сервисы.

**Ожидаемый результат:** пользователь видит только объекты своего портфеля. Все действия доступны только для чтения. Если нет сопоставимых измерений, интерфейс явно сообщает об этом, а не подставляет нули.

## US-03. Оператор хаба контролирует назначенный объект

**Роль:** `hub_operator`  
**Сущности:** `Site`, `Dashboard`, `Asset`, `Measurement`, `Event`, `ServiceInstance`  
**Статус:** просмотр поддерживается моделью; назначение объекта и управляющие действия требуют согласования.

1. Оператор открывает назначенный `Site`.
2. Просматривает `Dashboard`.
3. Проверяет статусы `Asset`: `online`, `offline`, `warning`, `error`.
4. Проверяет показатели и их `quality`.
5. Просматривает список `Event` и уровни важности `info`, `warning`, `critical`.
6. Просматривает подключённые `ServiceInstance`.

**Ожидаемый результат:** оператор получает актуальную для демонстрации картину объекта. Сценарий не предполагает подтверждение событий, изменение лимитов или отправку команд оборудованию.

## US-04. Собственник здания просматривает показатели

**Роль:** `building_owner`  
**Сущности:** `User`, `Site`, `Dashboard`, `Measurement`, `Asset`, `Event`, `ServiceInstance`  
**Статус:** просмотр поддерживается концепцией; назначение собственного `Site` пользователю не описано.

1. Пользователь открывает приложение.
2. Система показывает его `Site`.
3. Пользователь открывает `Dashboard`.
4. Просматривает потребляемую и генерируемую мощность, энергию потребления и выработки, отдачу в сеть, заряд батареи и лимит мощности — только если соответствующие измерения доступны.
5. Просматривает оборудование и события.

**Ожидаемый результат:** собственник видит данные своего здания в режиме чтения. Недоступные показатели не отображаются как нулевые.

## US-05. Пользователь открывает Dashboard объекта без батареи

**Роль:** любая из четырёх ролей с доступом к `Site`  
**Сущности:** `Site`, `Dashboard`, `Asset`, `Measurement`

1. Пользователь открывает `Site`, в котором нет `Asset` типа `battery`.
2. Система строит `Dashboard`.
3. Пользователь просматривает блоки показателей.

**Ожидаемый результат:** батарея не отображается как действующее оборудование. Не создаются фиктивные показатели заряда батареи.

## US-06. Пользователь открывает объект без подключённого сервиса

**Роль:** любая из четырёх ролей с доступом к `Site`  
**Сущности:** `Site`, `Dashboard`, `ServiceInstance`, `Measurement`

1. Пользователь открывает `Site`, где нужный сервис не подключён.
2. Система строит `Dashboard`.
3. Пользователь проверяет показатели сервиса.

**Ожидаемый результат:** показатели неподключённого сервиса не выдаются за реальные. Если отображается демонстрационный пример, он явно обозначен как `simulated` или другим согласованным способом.
