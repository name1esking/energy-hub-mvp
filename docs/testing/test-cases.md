# Тест-кейсы Energy Hub MVP

**Статус выполнения по умолчанию:** Not run.  
Все проверки выполняются на демонстрационных данных MVP.

| ID | Проверка | Шаги | Ожидаемый результат | Приоритет |
|---|---|---|---|---|
| TC-01 | Открытие приложения | Запустить приложение | Основной экран открывается без ошибки | High |
| TC-02 | Четыре роли | Проверить список ролей | Есть ровно четыре роли из `DATA_MODEL.md` | High |
| TC-03 | Доступ владельца портфеля | Выбрать `portfolio_owner`, открыть назначенный `Portfolio` | Видны только его `Site`; если назначения нет, тест Blocked до подготовки данных | High |
| TC-04 | Доступ оператора | Выбрать `hub_operator`, открыть назначенный `Site` | Видны данные назначенного объекта; неизвестные назначения отмечены как ограничение | High |
| TC-05 | Доступ собственника здания | Выбрать `building_owner` | Видны показатели своего `Site`; редактирование недоступно | High |
| TC-06 | Режим чтения портфеля | Войти как `portfolio_owner`, проверить кнопки изменения | Нельзя менять настройки, лимиты, оборудование и сервисы | High |
| TC-07 | Режим чтения здания | Войти как `building_owner`, проверить кнопки изменения | Нельзя менять настройки, лимиты, оборудование и сервисы | High |
| TC-08 | Статусы Asset | Открыть Site с разными статусами | `online`, `offline`, `warning`, `error` отображаются различимо | High |
| TC-09 | Нет батареи | Открыть Site без `battery` | Батарея не отображается как действующая; фиктивного заряда нет | High |
| TC-10 | Единицы Measurement | Открыть Dashboard | Мощность — кВт; энергия — кВт·ч; заряд — % | High |
| TC-11 | Пустое значение | Подать `value = null` | Показано отсутствие данных, не 0 | High |
| TC-12 | Качество complete | Показать Measurement с `quality = complete` | Данные обозначены как полученные | Medium |
| TC-13 | Качество missing | Показать Measurement с `quality = missing` | Отображается отсутствие данных | High |
| TC-14 | Качество stale | Показать Measurement с `quality = stale` | Отображается предупреждение об устаревании | High |
| TC-15 | Качество estimated | Показать Measurement с `quality = estimated` | Данные обозначены как расчётные | Medium |
| TC-16 | Качество simulated | Показать Measurement с `quality = simulated` | Данные обозначены как демонстрационные | High |
| TC-17 | Список событий | Открыть Site с Event | Видны заголовок, описание, важность, статус и время | High |
| TC-18 | Важность событий | Проверить `info`, `warning`, `critical` | Уровни различимы | Medium |
| TC-19 | Нет сервиса | Открыть Site без нужного ServiceInstance | Показатели неподключённого сервиса не выдаются за реальные | High |
| TC-20 | Peak Shaving | Открыть Site с подключённым Peak Shaving | Отображаются только доступные согласованные показатели | Medium |
| TC-21 | PV Self-Consumption | Открыть Site с подключённым PV Self-Consumption | Отображаются только доступные согласованные показатели | Medium |
| TC-22 | Запрет изменения лимита | Проверить UI лимита | Нельзя изменить лимит, пока право и механизм не согласованы | High |
| TC-23 | Запрет изменения Event | Проверить действия с Event | Не предлагаются неподтверждённые переходы статуса | High |
| TC-24 | Нет функции обслуживания | Открыть Asset | Не отображается фиктивное завершение обслуживания | Medium |
| TC-25 | Переключение Site | Переключить Site | Dashboard показывает данные выбранного Site, а не предыдущего | High |

## Как записывать результат

Для каждого теста указывать:
- фактический результат;
- статус `Pass`, `Fail` или `Blocked`;
- скриншот / описание ошибки;
- браузер и дату проверки.

Тесты, зависящие от отсутствующих в модели связей или операций, отмечать `Blocked`, а не `Fail`.
