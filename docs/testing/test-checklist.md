# Чек-лист тестирования Energy Hub MVP

Отмечать `Pass` / `Fail` / `Blocked` после фактической проверки. Сам документ не означает, что тесты уже выполнены.

## 1. Запуск и навигация
- [ ] Приложение запускается без ошибок.
- [ ] Основной экран открывается.
- [ ] Можно выбрать доступный `Site`.
- [ ] `Dashboard` открывается для выбранного `Site`.
- [ ] При смене `Site` данные Dashboard обновляются.

## 2. Роли и доступ
- [ ] В интерфейсе доступны только четыре роли: `platform_admin`, `portfolio_owner`, `hub_operator`, `building_owner`.
- [ ] Роль влияет на доступный набор объектов и представление Dashboard.
- [ ] `portfolio_owner` видит только назначенный `Portfolio` (после появления назначения в тестовых данных).
- [ ] `hub_operator` видит только назначенный `Site` (после появления назначения).
- [ ] `building_owner` видит только свой `Site` (после появления назначения).
- [ ] `portfolio_owner` не может менять настройки.
- [ ] `building_owner` не может менять настройки.
- [ ] Неодобренные управляющие действия оператора недоступны.
- [ ] Неавторизованный доступ не имитируется успешным действием.
- [ ] Ограничение: в MVP без backend проверяется только интерфейсная логика, не серверная безопасность.

## 3. Portfolio и Site
- [ ] `Portfolio` показывает связанные `Site`.
- [ ] Названия и типы объектов отображаются корректно.
- [ ] Нет дублирующихся объектов.
- [ ] Пользователь не видит объекты вне своей области доступа (после согласования связей `User`).

## 4. Asset
- [ ] Отображаются только существующие `Asset`.
- [ ] Типы `solar_panel`, `battery`, `inverter`, `meter`, `charger`, `load` отображаются корректно.
- [ ] Статусы `online`, `offline`, `warning`, `error` различимы.
- [ ] При отсутствии батареи батарея не показывается как действующее оборудование.
- [ ] Проблемное оборудование не отображается как исправное.

## 5. Measurement и качество данных
- [ ] Потребляемая и генерируемая мощность отображаются в кВт.
- [ ] Энергия потребления, выработанная энергия и отдача в сеть отображаются в кВт·ч.
- [ ] Заряд батареи отображается в %.
- [ ] Лимит мощности отображается в кВт.
- [ ] Каждое значение сопровождается единицей измерения.
- [ ] `value = null` отображается как отсутствие данных, не как 0.
- [ ] `complete` обозначает полученные данные.
- [ ] `missing` обозначает отсутствующие данные.
- [ ] `stale` обозначает устаревшие данные.
- [ ] `estimated` обозначает расчётные данные.
- [ ] `simulated` обозначает демонстрационные данные.

## 6. Event
- [ ] Отображаются `title`, `description`, `severity`, `status`, `timestamp`.
- [ ] Уровни `info`, `warning`, `critical` различимы.
- [ ] Примеры событий отображаются корректно.
- [ ] Не предлагаются неподтверждённые переходы статуса события.

## 7. ServiceInstance и Dashboard
- [ ] Подключённый сервис отображается для правильного `Site`.
- [ ] Неподключённый сервис не выдаётся за действующий.
- [ ] Peak Shaving отображает только доступные и согласованные показатели.
- [ ] PV Self-Consumption отображает только доступные и согласованные показатели.
- [ ] Dashboard учитывает роль, выбранный `Site`, оборудование, измерения и сервисы.
- [ ] При отсутствии батареи или сервиса соответствующие блоки не показываются как активные.

## 8. Ограничения операций
- [ ] Нельзя редактировать `Measurement` как способ изменения лимита.
- [ ] Изменение лимита не показывается как успешное, пока операция не согласована и не реализована.
- [ ] Подключение / отключение сервиса не показывается как успешное без реализации `ServiceInstance`.
- [ ] Обслуживание оборудования не показывается как завершённое без данных о работах.

## 9. Визуальная и общая проверка
- [ ] Нет пустых или сломанных блоков.
- [ ] Нет ошибок в консоли браузера.
- [ ] Длинные названия и отсутствующие данные не ломают экран.
- [ ] Демонстрационные данные визуально обозначены.
